# 竞品调研与可行性复核

> 2026-11-04 ｜ 目的：在写第一行代码前，确认「该不该做」和「该做多少」

---

## 结论摘要

1. **接口免费**。值得买 CTO 公开表述：接口长期免费，靠电商分佣覆盖成本。但有审核、有配额、政策可撤。
2. **同类产品已经很多，三层夹击**：官方 App 自带「降价提醒」、商业比价工具成熟、GitHub 上有活跃的开源实现（Java 11 + SQLite，昨天还在提交）。
3. **原方案 80% 是重复造轮子**。真正没人做的只剩一小块——同款多链接聚合 + 单价归一 + 可解释规则。建议把方案砍到这个范围，或者干脆不做。

## 一、接口是否收费

### 证据

值得买科技 CTO 王云峰在 2025 年 10 月的访谈中明确说：

> "在生态分佣模式上，**目前值得买科技的接口长期免费**，通过电商分佣覆盖成本后反哺合作伙伴。例如，用户通过 Agent 跳转消费的链接携带专属标识，佣金的大部分将分给流量的入口方。"

其商业化路径是：**免费开放接口抢生态位 → 推「销售联盟」做导购分佣 → 推「广告联盟」变现**。

### 但有四个必须知道的限制

| 限制 | 说明 | 对你的影响 |
|---|---|---|
| **需审核** | 手机号注册后申请测试 Key，审核通过才能调 | 可能被拒，尤其无企业主体 |
| **有配额** | "测试 Key"意味着有调用上限 | 20 分钟一次 ≈ 72 次/天，个人够用；高频拉全站会被限 |
| **免费是战略，不是合同** | 平台处于抢生态位阶段才免费 | 随时可能改成按量计费，方案要能降级 |
| **分佣绑定** | 跳转链接带专属标识，平台追踪佣金 | 自己用无所谓；若分享给别人用，涉导购资质，性质变化 |

### 两个入口，别搞混

| 平台 | 地址 | 定位 | 个人可行性 |
|---|---|---|---|
| 消费信息开放平台 | `openapi.zhidemai.com` | 老平台，appkey + 签名，`v1/youhui/list/show` 字段极全 | 偏企业合作，个人未必过审 |
| 海纳开放平台 | `ai.zhidemai.com/haina-platform` | 手机号注册即申请测试 Key，有好价检索 / 商品检索 / MCP | **推荐先试这里** |

**结论**：钱不是问题，审核才是。M0 阶段第一件事就是去申请，别等写完代码才发现拿不到 Key。

## 二、现成方案盘点

### 第 1 层：官方 App 自带「降价提醒」

值得买的 App 早就有这个功能，路径是：

```
复制任意商城商品链接 → 打开值得买 App → 首页「关注」→「我的商品」
→ 粘贴链接 → 查看历史价格趋势图 → 填入期望价 → 关注
```

- 数据来源：值得买多年积累的历史推荐价格
- 支持在「我的清单 → 降价监控」批量管理、改价、删除
- 低于期望价即推送 App 通知

**这一条直接命中了你的痛点一。** 你之前"白跑一趟"，很可能不是没有工具，而是没用这个功能，或者在网页端刷列表。

### 第 2 层：商业比价产品

| 产品 | 能力 | 短板 |
|---|---|---|
| **慢慢买** | 100+ 平台历史价、降价提醒、**关键词订阅折扣**、全网比价 | 关键词订阅只做推送，不做规则判定；同款多链接不聚合 |
| **购物党** | 180 天历史价、全网最低价、**微信降价提醒**、支持全网收藏 | 依赖浏览器插件，需常开浏览器 |
| **惠惠购物助手** | 历史价曲线、降价推送、隐藏券 | 同上 |

这三家把"历史价格 + 降价提醒"做成了红海，个人做不过它们的爬虫规模和数据积累。

### 第 3 层：GitHub 开源（最接近你原始设想）

**`PhantomStrikers/zdm`** —— 最后提交 2026-11-03（昨天），仍在维护。

| 项 | 情况 |
|---|---|
| 技术栈 | Java 11 + Maven + SQLite + Hibernate（**和你的栈一致**） |
| 数据源 | 值得买好价排行榜分页接口 + selenium 自动取 cookie |
| 过滤 | 标题白名单 / 黑名单（白名单优先）、`minVoted`、`minComments` |
| 推送 | 邮件（SMTP）、微信（WxPusher） |
| 去重 | SQLite 记录已推送，`COMMIT_THRESHOLD` 控制提交频率 |
| 运行 | GitHub Actions 定时，cron 可配（示例 15 分钟一次），**无需自己搭服务器** |
| 成本 | 0（Actions 免费额度足够） |

同类还有 `llq164850128/SMZDM_Monitor_Parice`（Python，关键词匹配 + 邮箱/QQ 推送）、以及 `xinrukon/zdm` 等若干 fork（加了白名单）。

**它的 CHANGELOG 里有一条重要情报**：

> 2025/10/25 删除环境变量 `cookie`，**最近检测变严格了，固定的 cookie 是走不通的**

说明值得买的风控在收紧。这既解释了为什么官方接口更值得走，也说明自己写爬虫的维护成本会持续上升。

## 三、能力对比：还剩下什么没被覆盖

| 能力 | 值得买 App | 慢慢买/购物党 | zdm 开源 | 缺口 |
|---|:---:|:---:|:---:|:---:|
| 单链接目标价提醒 | ✅ | ✅ | ❌ | — |
| 历史价格曲线 | ✅ | ✅ 180天 | ❌ | — |
| 全站关键词订阅推送 | ❌ | ✅ | ✅ 白名单 | — |
| 值/评论数门槛过滤 | ❌ | ❌ | ✅ | — |
| 固定 cookie 免登录 | — | — | ✅ | — |
| **同款多链接聚合**（一个规格，几十个爆料链接） | ❌ | ❌ | ❌ | **有** |
| **单价归一**（元/L、元/包） | ❌ | ❌ | ❌ | **有** |
| **规则组合 + 可解释**（为什么推给你） | ❌ | ❌ | ❌ | **有** |
| **命中率复盘**（推了 20 条买了几条） | ❌ | ❌ | ❌ | **有** |
| **误报自学习**（不感兴趣 → 自动排除词） | ❌ | ❌ | ❌ | **有** |

前四行说明：**你的原始需求已经被覆盖了。**
后五行说明：真正没人做的，是一个**很窄的东西**——

> 针对「有明确品牌和规格、但同一规格在站内有几十个不同链接」的商品（机油、猫粮、抽纸、充电宝），做多链接聚合 + 单价排序 + 可解释的规则判定。

为什么商业产品不做？因为对大众用户太复杂，设置门槛高、收益不明显。为什么 App 不做？因为它的提醒模型是绑 SKU 的，天然做不了"规格级聚合"。

## 四、建议路径

### 阶段 0：先证明它不是伪需求（零代码，本周就能做完）

1. 打开值得买 App，把**已知型号**的商品（笔记本、充电宝）用「降价提醒」挂上，设好期望价
2. 用两周
3. 记录：推送了几次、点了几次、买了几次

**这是最重要的一步。** 如果它已经解决了 80%，后面所有代码都不该写。

### 阶段 1：只补那块缺口（仅在阶段 0 证明不足时）

不要从零写。fork `PhantomStrikers/zdm`，它已经解决了采集、去重、推送、cookie、定时五个脏活。

你只需要加三个增量：

1. **规格聚合**：把 `required_terms` 匹配到的多条爆料，按"规格归一化"聚成一组，取最低单价
2. **规则判定**：把它的黑白名单升级成条件树（目标价 / 单价 / 值率 / 商城）
3. **桌面通知 + 看板**：Toast 已验证可用；看板记录命中率

工作量从"一个系统"降到"三个模块"。
