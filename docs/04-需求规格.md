# 需求规格（v1 · 可开发）

> 2026-11-04 ｜ 基于 8 组关键词、点值+评论数判定、1 小时时效、B 模式仅神价即时推

---

## 1. 两类场景的最终定义

### 模式 A：关键词守候（目的性）

**用户动作**：搜 `5w-30机油` → 看前几条 → 看点值和评论 → 点进去

**系统接管的部分**：
- 替代「反复搜 8 组关键词」→ 一次拉全站流，本地匹配全部组
- 替代「看前几条」→ 增量识别新爆料
- 保留「看值/评论」→ 作为热度门槛
- 替代「点进去才发现失效」→ 推送前先验有效期

**成功标准**：从「1-3 天发现一次且大概率失效」变成「30 分钟内发现且有效」。

### 模式 B：神价发现（无目的性）

**用户动作**：刷榜单 → 看到价格离谱便宜 → 考虑入手

**系统接管的部分**：
- 替代「刷榜单」→ 定时扫榜单，只挑符合"特别便宜"的
- 补上「相关性判断」→ 不推完全无关的品类
- 补上「重复判断」→ 已有同类物品则降权

**成功标准**：一周推 2-3 条，每条你都点进去看了。

## 2. 查询意图与归一化匹配

### 2.1 用户只输入意图，不维护词表

**修正**：上一版把「换很多关键词」理解成「用户有一批固定词表要配置」，是错的。
真实痛点是**搜索查全率低**——同一个商品有多种写法（`5W-30` / `5W30` / `5w30`），平台的搜索往往只匹配其中一种，用户只能靠反复换词来补召回缺口。

所以系统要做的是**替代人肉试错**，而不是让用户去维护一张更复杂的词表。

配置形态：

```yaml
intents:
  - keyword: "5w-30机油"      # 一句话，原样输入
    expand: SYNONYM            # NORMALIZE / SYNONYM / BROAD
    category: AUTO_FLUID
    priority: HIGH
    hot_level: LOW
    exclude: [柴油, 摩托车, 二手, 翻新]   # 可留空，系统给默认值
    enabled: true

  - keyword: "充电宝"
    expand: SYNONYM
    category: POWER_BANK
    hot_level: MEDIUM

  - keyword: "牛奶"
    expand: SYNONYM
    category: DAIRY
    hot_level: LOW
```

用户填一个关键词 + 选一个扩展档位。**扩展词由系统生成，不落到配置里**。

### 2.2 三层召回（扩展档位）

| 档位 | 做什么 | 误报风险 | 默认 |
|---|---|---|---|
| `NORMALIZE` | 去横杠/空格/标点、统一大小写、全角转半角 | 零 | 必开 |
| `SYNONYM` | 在归一化基础上加同义词（机油↔润滑油、美孚↔Mobil） | 低 | **推荐** |
| `BROAD` | 再加上位词（`5w-30机油` 也吃 `机油`） | **高** | 默认关闭 |

**为什么 BROAD 默认关**：`5w-30机油` 扩到 `机油`，会把 0W-40、柴机油、摩托车油全部召回。这是最致命的一类误报，一次就够让系统失信。

### 2.3 归一化规则（第一层，主力）

```
输入: 5w-30机油
归一: 5w30机油

标题: 美孚（Mobil）1号 全合成机油 5W30 SN级 4L 汽车保养
归一: 美孚1号全合成机油5w30sn级4l汽车保养

判定: 归一化标题包含 归一化关键词 → 命中
```

处理项：
- 去除 `-` `－` `–` `_` `·` 空格、括号及全角标点
- 全角转半角
- 统一小写
- 中文数字与阿拉伯数字（`五升` → `5l`）

### 2.4 数字硬约束（防误报的核心）

**归一化可以动符号，绝不能动数字。**

```
5W-30 → 5W30    ✅
5W-30 → 0W-40   ❌ 禁止
```

实现方式：

```
1. 从关键词中抽取「数字+字母」token 集合：{5w30, 4l}
2. 从标题中抽取同样的 token 集合
3. 要求关键词的 token 集合 ⊆ 标题的 token 集合
4. 只有剩余的自然语言部分允许模糊匹配
```

这一步必须在代码里硬编码，不提供配置项——它比任何阈值都重要。

### 2.5 同义词表（第二层，小词表）

由系统维护，用户可增删，但**不需要从零填**：

```yaml
机油: [润滑油, 引擎油, 发动机油]
充电宝: [移动电源, 充电宝, 便携电源]
美孚: [Mobil, 埃克森美孚]
壳牌: [Shell, 喜力]
牛奶: [纯牛奶, 全脂奶]
```

规模控制在 50 条以内，覆盖你常买的品类即可。可选：用 LLM 生成候选，人工确认后入库。

### 2.6 排除词的默认值

用户通常懒得填排除词，系统按品类给默认值，用户只需在误报时点一下「不感兴趣」，自动追加：

| 品类 | 默认排除 |
|---|---|
| 机油 | 柴油、摩托车、二冲程、齿轮油、防冻液 |
| 牛奶 | 乳饮料、含乳饮品、奶粉、酸奶、临期、清仓 |
| 数码 | 二手、翻新、官换、配件、保护壳、贴膜 |
| 通用 | 租赁、试用装、小样、赠品 |

### 2.7 8 个意图以上的管理

- 按 `category` 折叠，默认只展开启用的
- 批量启停（换季时关掉一批）
- 每组独立热度阈值（见 §3.2）
- 导入导出

**配置总量对比**：从「8 组 × 每组 5-10 个词 + 排除词」降到「8 句话」，扩展和维护都由系统承担。

## 3. 判定模型

### 3.1 主流程

```
拉取好价流（增量）
  → 过滤 sold_out / timeout
  → 阶段一：分组匹配
      命中任意 group 的 terms 且不命中该组 exclude  → 归为 A 类
      未命中任何 group                              → 进入阶段二
  → 阶段二：神价发现（仅 B 类）
      满足「特别便宜」三条件 且 品类在兴趣画像内     → 归为 B 类
  → 阶段三：热度门槛
      worthy ≥ 该组阈值  AND  comments ≥ 该组阈值
  → 阶段四：有效期检查
      check_tips 含"有效" / 距 pubdate < 6 小时
  → 去重 → 推送
```

### 3.2 热度阈值（按组配置，解决冷门品类）

| hot_level | worthy 下限 | comments 下限 | 适用品类 |
|---|---|---|---|
| `HIGH` | 100 | 30 | 笔记本、显卡、手机 |
| `MEDIUM` | 30 | 10 | 充电宝、耳机、小家电 |
| `LOW` | 8 | 3 | 机油、猫粮、抽纸、牛奶 |

**为什么必须分档**：机油好价爆料常常只有 10 个点值，全站统一设 50 会让机油永远不触发。这是最容易犯的错。

首次配置时系统按品类给建议值，用户可改。跑两周后，看板给出「该组平均热度」供校准。

### 3.3 「特别便宜」的定义（模式 B）

```
(命中 zhifa_tag 中的 神价格 / 绝对值 / 历史低价
 OR 折扣深度 ≥ 50%           # digital_price / page_price ≤ 0.5，仅兜底
)
AND worthy ≥ 50
AND comments ≥ 10
AND 品类 ∈ 兴趣画像（由 A 组关键词反推）
AND 该品类近 90 天未推送过同类神价
```

**折扣深度不可靠**：它基于页面价，而页面价常是虚高原价。所以官方标签优先，折扣深度只做兜底，且必须在推送文案里注明依据。

### 3.4 有效期检查

| 接口字段 | 判断 |
|---|---|
| `article_is_sold_out = 1` | 跳过 |
| `article_is_timeout = 1` | 跳过 |
| `check_tips` 含「无效」「失效」 | 跳过 |
| `pubdate` 距今 > 6 小时 | 降级：仍推但在文案标注「可能已失效」 |

## 4. 调度参数

| 项 | 值 | 理由 |
|---|---|---|
| 好价流拉取 | **每 30 分钟** | 用户要求 1 小时内；平均延迟 15 分钟，留足处理时间 |
| 取数方式 | **一次拉全站流，本地匹配全部组** | 请求量与关键词组数解耦，加到 50 组也不增加调用 |
| 增量游标 | 上批最大 `pubdate` | 避免重复拉取 |
| 单次翻页 | 5 页（约 100 条），不足则扩 | 全站好价 30 分钟增量通常 < 100 条 |
| 日请求量 | ≈ 48 次 + 重试 | 远低于配额风险线 |
| 静默时段 | 23:00–08:00 | 高优先级组可单独关闭静默 |

**关于夜间**：机油这类抢手货可能凌晨出好价。所以静默是"每组可配"，不是全局强制。默认高优先级组夜间照推，低优先级组静默到 08:30 汇总。

## 5. 推送设计

### 5.1 模式 A 通知

```
【机油 · 命中 5w-30】
美孚1号 全合成 5W-30 4L  ¥238
点值 26 · 评论 11 · 京东自营
30 分钟前发布 · 券后价
→ 查看
```

必备四要素：**命中哪一组**、**实付价**、**热度**、**发布时间**。
「命中哪一组」是信任的基础——你配置了 8 组，必须知道是哪一组的规则触发的。

### 5.2 模式 B 通知

```
【神价 · 绝对值】
某品牌 65W 氮化镓充电器  ¥39（日常 ¥129）
点值 420 · 评论 186 · 京东
→ 查看
```

必带：**便宜的依据**（命中什么标签）、**折扣幅度**、**热度**。

### 5.3 合并与冷却

| 规则 | 值 |
|---|---|
| 同 `article_id` | 永久只推一次 |
| 同组 10 分钟内多条 | 合并成一条，列前 3 |
| 同组 24 小时内同类商品 | 降权，除非更便宜 20% 以上 |
| 模式 B 同品类 90 天 | 只推一次 |

## 6. 数据模型调整

在 `01` 的基础上新增/修改：

```sql
CREATE TABLE watch_group (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,              -- 机油
  category TEXT,                   -- AUTO_FLUID，映射品类模板
  priority TEXT,                   -- HIGH / NORMAL / LOW
  hot_level TEXT,                  -- HIGH / MEDIUM / LOW
  exclude TEXT,                    -- JSON array
  enabled INTEGER DEFAULT 1,
  quiet_hours INTEGER DEFAULT 1    -- 是否受静默时段约束
);

CREATE TABLE group_term (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  group_id INTEGER NOT NULL,
  text TEXT NOT NULL,
  mode TEXT NOT NULL               -- EXACT / FLEX
);

CREATE TABLE match_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  article_id TEXT,
  group_id INTEGER,
  match_type TEXT,                 -- A_KEYWORD / B_DEAL
  matched_term TEXT,               -- 命中的具体词，用于解释
  worthy INTEGER, comments INTEGER,
  pushed_at TEXT, clicked_at TEXT, feedback TEXT
);
```

`match_log` 里的 `matched_term` 是关键：没有它，你无法回答"为什么推给我"，也就无法调优。

## 7. 兴趣画像（由 A 喂养 B）

```
兴趣画像 = 所有启用 group 的 category 集合
         + 权重（按该组近 30 天命中次数加权）

模式 B 筛选时：
  category ∈ 画像        → 正常推送
  category ∉ 画像        → 丢弃
  同品类近 90 天有推送   → 降权 50%
```

不需要用户额外配置，用得越久越准。
